# 프로세스 — 어떻게 수행하는가

> **이 디렉토리는 규칙이 아니라 흐름을 적는다.** 규칙(*"하지 마라"*)은
> [`.claude/rules/`](../../.claude/rules/) 가, 과거 실패(*"이렇게 틀렸었다"*)는
> [`.claude/traps.md`](../../.claude/traps.md) 가, **작업을 어떤 순서로 진행하는가**는 여기가 담는다.

## 왜 신설했나

사용자 관찰: *"문서가 룰을 보강하는 방식으로 쌓였는데, 정작 중요한 것은 어떻게 수행하고
어떤 프로세스와 플로우로 진행되어야 하는가다."*

그 관찰을 실증한 실수 3건(반례 하나 막고 봉인 선언 ·
행위를 결과로 보고 · 고아 커밋을 완료로 단언)은 **규칙이 없어서가 아니라** 규칙은 있는데
*"어떻게 진행하는가"* 가 없어서 났다. 규칙은 상태를 말하고, 프로세스는 순서를 말한다.

## 이 디렉토리의 규약

- **한 문서 = 한 흐름.** 참조 정보는 넣지 않는다(그건 `docs/reference/`).
- **순서가 본문이다.** 번호 단계로 쓰고, 각 단계에 *"무엇을 확인하면 다음으로 가는가"* 를 적는다.
- **실패 지점을 단계 안에 적는다** — 어느 단계에서 무엇이 깨졌는지가 그 단계의 존재 이유다.
  상세 기전은 [`traps.md`](../../.claude/traps.md) 를 가리킨다(여기 복제하지 않는다).
