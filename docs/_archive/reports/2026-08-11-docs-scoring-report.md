## 1. 채점 체계

### 1-1. RRS(문서 채점) — 계측기로만 보존, **순위 발행 금지**

`RS = HRS − CRS`, `HRS = 100·N·B·D·U`, `CRS = 100·(1−B)·s_age·(1−lg(sessions+reads,8))`. 재현: `scratchpad/rrs3.py`.

발행을 금지하는 이유는 3건이며 전부 실행으로 확인됐다.

| 결함 | 실측 |
|---|---|
| 편집 불변성 없음 | 처분 26건의 `days_since_edit`만 0으로 바꾸면 **26/26이 "조치 없음"으로 소멸** |
| 관측자 오염 | 감사 세션 자신이 분모 8세션 안에 있고, 재수집하면 삭제후보 17 중 7건 이동 |
| 접근축 무효 | `sessions_touched`의 93%가 린터 파일목록·`ls`·`git status` 부수 등장 |

### 1-2. AR(조치 채점) — 이번 계획의 확정 수식

```
AR = f × s × e × i
f 반증가능성 {0,1}   지금 리포에서 red 를 만들 수 있는가. f=0 → 기각
s 심각도 {1,2,3}     3 런타임 파손·시크릿 노출 / 2 잘못된 지시 발행 / 1 값 drift
e 집행상태 {1,2,3}   3 거짓 집행자 / 2 집행자 0 / 1 부분
i 독립성 {0.5,1}     선행 의존 시 0.5
```
사람이 매기는 항목은 `s` 하나뿐(재현 절차 위에 고정). 경계: **AR≥6 즉시 착수 · 3~4 계획 · ≤2 후순위 · f=0 기각**.

|---|---|---|

| E SESSION_SECRET · J 처분 철회 | 1·3·2·1 | **6** |
| A pylint · D 가드개수 · F 배선 · G architecture | 1·2·2·1 | **4** |
| C 게이트 예산 | 1·2·3·0.5 | 3 |

| ~~R3 C6 shared 매핑~~ | f=0 (`services.md` frontmatter 에 이미 존재) | 기각 |
| ~~RRS 처분 26건~~ | f=0 (편집 1회로 소멸) | 기각 |
