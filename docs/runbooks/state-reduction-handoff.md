## 5. 압축할 때 무엇을 남기는가 (C7) — 작업 절차

정본 = [`.claude/traps.md` §C7](../../.claude/traps.md). 단위 3(`#1360`) 이 PR 번호 귀속 · Grok 반증 기록 · 결함명 · `UNVERIFIED` 를 지웠고 가드는 전건 초록이었다. 적대 검증이 4줄을 적발했고, **나머지를 같은 축으로 대조시키니 10줄이 더** 나왔다(총 14). 가장 나빴던 줄은 단위 3 시점 L302 — *«봉인 주장 안 함»* 만 남고 **왜** 가 사라졌다. 그 번호는 이후 밀렸으니 지금 STATE 의 L302 가 아니다.

가드는 항목 수·문자 수·사슬만 본다. 이 축은 기계가 닫지 못한다.

**전제: 이 순서는 원장 불릿(`§테스트 수 추적 이력` 의 `- ` 항목)에만 적용한다.**
표 셀(옵션 C)에는 `git show <부모>` 로 짝지을 «같은 항목» 이 없다. C 는 §2 를 보고, 이 6단계를 표에 억지로 얹지 마라.

**따라할 순서** (단위 3 이 복원 후 쓴 것 + 빠졌던 단계):

0. **뮤테이션을 돌릴 거면 먼저 `git add -A`.** [`.claude/rules/guards.md`](../../.claude/rules/guards.md) §뮤테이션 복원 순서 — `git checkout --` 는 index 를 되살린다. 안 하면 복원이 방금 쓴 편집까지 지운다.
1. **사실 토큰과 서사를 나눈다.** 사실 토큰 = PR/이슈 번호 · 세션 ID(`019f…` / `01a0…` / `wf_…`) · 결함명 · 검증 상태(`UNVERIFIED` / `VERIFIED` / `BROKEN`) · backlog ID · 교차참조. 서사 = 기전 재설명 · 형용 · 다른 문서에 있는 배경.
2. **서사만 버린다.** 사실 토큰은 줄인다 해도 한 줄에 남긴다.
3. **배치를 끝낸 뒤 전수 대조한다.** 첫 적대 보고가 전수라는 보장이 없다. 질문: *이 배치의 각 줄에서 사실 토큰이 원문에 있었는데 빠졌는가?* 원문 = `git show <부모>:docs/STATE.md` 의 같은 항목.
4. **적발분을 고친 뒤 나머지 전부를 같은 축으로 다시 본다.** 4건 보고 → 실제 14건이 이 세션의 실측이다.
5. **복원은 사실 토큰만.** 서사를 되살리지 않는다. 그 다음 `py -3 scripts/check_state_ledger.py` 를 돌린다. 감축이 보이면 **같은 PR** 에서 `py -3 scripts/check_state_ledger.py --update-baseline` 과 `tests/unit/scripts/test_state_ledger.py` 의 `_MIN_ITEMS_FLOOR` / `_MIN_CHARS_FLOOR` 를 함께 고친다. 이 단계가 없으면 CI 가 red 에서 끝난다(§3-1 M2).
6. **claim-review 를 압축 PR 에 붙인다.** C7 가 그 이유다. 가드 초록 ≠ 내용 보존.

다른 곳에 없는 산식·이중 계상·형식 쌍 2개짜리 항목은 거의 줄이지 않는다(단위 3 이 `#1060~#1066` · `#1346` · `#1279~#1282` 를 남긴 이유).

**게이트 창 안을 편집하면 R80 을 만난다.** §현재 수치·헤더는 창 안이다. `#1357` 이 그때 한 일은 §2-2 막힘 1. 새 우회를 여기서 규정하지 않는다.
