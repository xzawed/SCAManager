# 함정 목록 — 이 저장소가 실제로 밟은 것

> **이 파일은 규칙이 아니다.** 규칙은 *"하지 마라"* 이고, 여기는 *"이렇게 틀렸었다"* 다.
> 규칙은 집행자가 지키고(`🔴` = 집행자 동반), 함정은 **사람이 기억해야** 한다 —
> 집행자를 만들 수 없는 축이기 때문이다.
>
> **새 항목은 실제로 밟은 뒤에만 추가한다.** 추측성 함정은 넣지 않는다 —
> 그 순간 이 파일도 아무도 안 읽는 규칙 더미가 된다.

## 왜 이 파일이 생겼나 (2026-08-13)

사용자 관찰: *"문서가 룰을 보강하는 방식으로 쌓였는데, 정작 중요한 것은 어떻게 수행하고
어떤 프로세스로 진행하는가다."* 실측이 그것을 뒷받침했다:

| 축 | 값 |
|---|---:|
| `🔴` 규칙 | 307건 |
| 그중 **집행자 없음** | **221건 (72%)** |
| 룰·정책 텍스트 | 112,589자 |
| 집행자(가드+테스트) | 970,258자 (**8.6배**) |

그리고 2026-08-12~13 세션에서 실제로 무엇이 실수를 막았는지 세어보니 —
**기계 가드 12회 · 실패 클래스 기억 7회 · 외부 적대 검증 4회 · 룰 텍스트 ≈0회** 였다.

그래서 **집행자 없는 `🔴` 221개를 전부 뗐고**(규칙문은 남겼다), 그 안에 있던 **실패 기전을
여기로 모았다**. 규칙을 늘리는 것은 처방이 아니었다.

## A. 관측자가 거짓말하는 형태 (observer-lie)

이 저장소의 **최다 재발 클래스**다. 코드는 고쳤는데 관측자가 계속 초록을 보고한다.

### A1. 산문이 가드를 통과시킨다
`echo 'WARNING: tsc install failed'` 경고 문구만 남아도 *"조달됨"* 으로 판정됐다(`#1136`).
*"사용자 회신 **대기**"* 라는 산문이 안전등급 자기인증 방지를 통과했다(`#1156`).
→ **통과 조건이 `X in text` 면 fail-open 이다.** AST 또는 실행 관측을 쓴다.

### A2. 합성 픽스처는 증명이 아니다
`#1121` 이 합성 입력으로 *"뮤테이션 실증"* 을 PR 에 적었으나, 실제 `scheduler.py` 를 넣으니
docstring 이 마커를 만족시켜 축이 죽어 있었다.
→ 뮤테이션 대상은 **그 가드가 보호한다고 주장하는 실제 경로**여야 한다.

### A3. 정의 ≠ 배선
`#1145` 스모크 훅의 감시 확장이 순수 함수엔 있는데 `main()` 이 게이트해 **런타임에서 통째로 dead**.
테스트는 순수 함수만 봤다. `#1156` 은 진단만 있고 집행면이 없었다.
→ *"실제 게이트(ci/pre-commit/훅)에 배선됐나"* 를 **실행으로** 관측한다.

### A4. 기대값을 피검사 대상에서 유도하면 공허해진다
`doc_review_gate` 컨텍스트 가드가 기대 목록을 `_CONTEXT_SOURCES` 에서 읽었더니,
**원천을 삭제하면 루프가 안 돌아 GREEN** 이었다.
→ 기대값은 테스트 쪽에 **리터럴로 못박는다**. 지문도 그 원천에만 있는 문구를 쓴다.

### A5. 거짓 집행자가 무집행보다 나쁘다
합계만 검사하는 가드는 거짓을 초록으로 **보증**한다. 못 재는 자리에는 가드를 두지 않는다 —
한계를 적는 편이 낫다.

### A6. delta 만 보면 분모 소실을 못 본다
`check_red_budget` 이 *"무집행 `🔴` 이 늘었는가"* 만 봐서, `guards.md`+`docs.md` 를 **삭제**하면
221→171(Δ−50) 로 **개선을 보고**했다(2026-08-13 실측). 가드를 지우는 것이 가장 값싼 개선이었다.
→ 비율을 재는 게이트는 **분모가 사라지는 경우**를 따로 봐야 한다.
**분모 축을 만들었어도 그 축이 안 도는 실행 경로가 남는다** — 그 축은 `PR_BASE_SHA` 분기에만
살아서, 로컬 실행은 표면을 통째로 지워도 `100.0% · 무집행 0건` + **EXIT 0** 을 인쇄한다
(Grok `019ffb93` 반례 (d)). *안 쟀음*을 *통과*로 인쇄하지 마라.
집행: `tests/unit/scripts/test_red_budget.py::test_local_run_says_the_denominator_axis_was_not_measured`.

### A7. 마커를 세는 가드는 **마커 위장**에 뚫린다
집행 여부를 *"`🔴` 이 있는 줄"* 기준으로 세면, 독자에게 똑같이 빨간 필수 규칙으로 보이는
**🛑** 로 쓴 줄은 카운터에 **존재하지 않는다**. *"무집행 🔴 = 0"* 이 참인 채로 무집행 필수
규칙을 무한히 쌓을 수 있다(2026-08-13 Grok 반례 (e) — 실경로 뮤테이션 25 passed).
→ 표기로 판정하는 가드는 **동의어 집합**으로 닫는다. 반례 하나를 막고 끝내면
같은 클래스의 다음 인스턴스가 곧 들어온다(AGENTS.md §불변식 2-b).
→ 그래도 **열거는 완결되지 않는다** — 임의의 새 표기(`**[필수]**` 등)는 여전히 통과한다.
집행: `tests/unit/scripts/test_red_budget.py::test_lookalike_red_markers_are_counted_too`
(과교정 대조군 `test_caution_and_bad_example_glyphs_are_not_rule_markers` 동반 — ⚠/❌ 까지
세면 *한계를 적는 행위*에 벌점이 붙어 이 리포가 지키려는 것의 정반대가 된다).

## B. 검증이 스스로를 속이는 형태

### B1. 측정 도구가 나보다 먼저 거짓말한다
- `git stash` 왕복이 인덱스를 흐트러뜨려 `git ls-files` 가 옛 경로를 반환 → parametrize 테스트
  **29건 red**. 코드는 멀쩡했다(2026-08-13).
- `git ls-files` 는 머지 충돌 중 같은 경로를 3-stage 로 출력해 **개수를 부풀린다**.
- 도구가 틀렸으면 그 도구로 만든 관측도 틀린다 — **자기 점검이 원리적으로 불가능**하다.
→ 이상한 수치를 *"내 오판독"* 으로 닫기 전에 **계기 오염을 먼저 배제**한다.

### B2. 뮤테이션이 GREEN 이면 가드 공허를 묻기 전에 뮤테이션 유효성부터
`assert mutated != orig` 없이 *"안 잡혔다"* 고 결론내지 않는다.
실측: 뮤테이션이 **엉뚱한 줄에 적용**돼 통과한 것을 "테스트가 공허하다"로 오진할 뻔했다(2026-08-13).
동작을 바꾸지 않는 no-op 뮤테이션(`ensure_ascii=True` → 기본값)도 같은 함정이다.

### B3. 내 뮤테이션은 내가 상상한 실패 모드만 고른다
외부 반례를 받아 그 반례만 막고 *"fail-open 을 닫았다"* 고 선언한 사례가
**한 세션에 2회**(`#1335` 아카이브 가드 · `#1340` 초판).
→ 규율: `AGENTS.md` §불변식 2-b (반례 일반화 + 봉인 선언 금지).

### B4. 가드의 첫 실사용이 그 가드의 잠재 결함을 드러낸다
`STATE-sync-deferred` 마커를 **처음 실제로 쓰자** squash 로 tip 에 실렸고,
그 마커를 읽는 함수의 fail-open 이 즉시 발현해 main 이 red 가 됐다(`#1335`→`#1337`).
영구 skip 되던 가드를 활성화할 때도 같은 일이 난다.
→ 새 기능의 **첫 사용은 검증 대상**이다.

### B5. 산문 가드는 양방향으로 틀린다
부정어·어휘 탐색은 **정정 기록을 막는다** — *"내 봉인 주장은 거짓이었다"* 라는 문장이
seal 어휘 탐지에 걸려 3회 차단됐다(2026-08-13). 반대로 의미 반전은 통과한다.
→ **인용 면제가 필수**다. 열거·구조 문맥으로 판정하고, 정정을 막지 않는지 확인한다.

## C. 문서·수치가 조용히 갈라지는 형태

### C1. N지점 손유지는 N−1번의 실패 기회
같은 정수가 5곳에 복제돼 있었고, 이력이 표 셀 안에 있던 시절 그 줄은 30,806자였다 —
머리와 꼬리가 30,752자 떨어져 한쪽만 고치는 사고가 실제로 났다.
→ 손유지는 **1지점**, 나머지는 파생. `check_docs_sync --fix` 가 그 파생자다.

### C2. 문서를 옮기면 관측자가 조용히 죽는다
경로를 하드코딩한 소비자가 실재한다 — 스크립트·훅·테스트·CI.
2026-08-13 재편에서 3건이 실제로 깨졌다(스캐너 범위 9→3 · 등급 패턴 유입 · 이스케이프 잔재).
→ 이동 전 **`grep -rn` 전수**. 이동 후 전체 스위트 + 게이트.

### C3. 압축은 픽스처·앵커·잔여를 깨뜨린다
2026-08-13 backlog·cycle-history 압축에서 3축이 동시에 깨졌다 —
✅ 행에 숨은 **미해결 잔여 21건**(그중 17건은 귀속처 없음) · TOC 앵커 2건 ·
실물 픽스처를 쓰던 테스트 1건.
→ 압축 착수 전 3문: **(a) 이 파일을 픽스처로 쓰는 테스트가 있는가 (b) 앵커·링크 소비자가
있는가 (c) 지워지는 내용에 열린 일감이 있는가.**

### C4. 인용한 `file:line` 은 자연 drift 로 거짓이 된다
추정 라인은 조용히 틀려진다(실사고 5건). `grep -n` 실측값만 쓰고, 가능하면 커밋 해시를 병기한다.
2026-08-13 에는 `CLAUDE.md` 자신의 *"README 21~25줄 배지"* 인용이 **충돌 마커를 가리키고** 있었다.

### C5. 본문만 고쳐서는 required check 가 갱신되지 않는다
PR 본문 편집은 이벤트를 재생하지 않는다 — **커밋을 하나 더 밀어야** 한다(실측 4회).

### C6. 커밋 해시로 머지를 단언하지 마라
정정 커밋을 **이미 머지·삭제된 브랜치**에 63분 뒤 얹어 고아가 됐는데,
인계 문서가 *"(#1335 에 포함)"* 이라고 단언했다(2026-08-13). push 출력의 `* [new branch]` 가
신호였는데 놓쳤다.
→ *"포함됐다/머지됐다"* 는 `git merge-base --is-ancestor` 실측 동반.

## D. 파괴적 작업의 함정

### D1. `write_text` 는 인코딩 전에 파일을 비운다
치환 문자열에 lone surrogate 가 섞여 `UnicodeEncodeError` 가 나자
`doc_review_gate.py` 가 **0바이트**가 됐다(2026-08-05 실제 사고).
→ (a) 편집 전 `git add` 로 기준선 stage (b) 가능하면 Edit 툴 (c) 부득이 스크립트면
`s.encode("utf-8")` 로 **먼저 인코딩 검증**.

### D2. 뮤테이션 복원은 index 를 되살린다
`git checkout -- <파일>` 은 HEAD 가 아니라 **staging area** 를 되살린다.
`git add` 없이 뮤테이션→복원하면 **내가 쓴 편집까지 지운다**.
→ 순서: `git add -A` → 뮤테이션 → `mutated != orig` 확인 → red 관측 → `git checkout --` → green 확인.

## E. 협업의 함정

### E1. Grok 은 `read-only` 를 무시할 수 있다
`sandbox: read-only` 로 호출했는데 rules 2파일(105줄·134줄)이 삭제된 채 돌아왔다(2026-08-13, 2회).
Windows 는 커널 강제가 불완전하다.
→ **`worktree: true` 로 격리**하거나 사전 `git add` 로 기준선을 고정한다. 격리 후 재발 0.

### E2. 외부 검증은 내가 준 맥락만큼만 본다
Grok 이 정확한 반례를 준 것은 프롬프트에 과거 사고를 넣어줬기 때문이다.
→ **이 파일이 그 맥락의 출처다.** claim-review 프롬프트에 관련 함정을 인용한다.

## 이 파일이 하지 못하는 것 (정직 기준)

- **집행하지 않는다.** 여기 적힌 것은 전부 사람이 기억해야 하는 축이고,
  기계로 잴 수 있었다면 가드가 됐을 것이다.
- **완전하지 않다.** 밟은 것만 적혀 있다. 안 밟은 함정은 여기 없다.
- **읽히지 않으면 0이다.** `CLAUDE.md` 진입점과 claim-review 프롬프트가 유일한 도달 경로다.
